# Turn table — WhatsApp behaviour cases (A/B/C/D)

Artifact for WP0 of the 2026-10-19 implementation package. It turns the trace recheck section of
`analysis/2026-10-19-whatsapp-behavior-cases/implementation/00-context-cases-traces.md` into a per-turn table so that later work
packages can cite stable turn ids (A1–A7, B1–B9, C1–C12, D1–D4).

- Generated: 2026-10-20 (UTC).
- Rows: 32 runtime turns (A=7, B=9, C=12, D=4). Turn order = ascending `captured_at`.
- Read-only throughout: no DynamoDB write, no backend write, no deploy. `POST /messages` was never called.
- Every number below carries its source (perf `trace_id`, stored OpenAI `response_id`, or endpoint + query).

## How each fact was obtained

| Code | Source | How it was queried |
|---|---|---|
| `P` | DynamoDB turn perf record | table `recap-agent-runtime-perf` (prod Lambda env `PERF_TABLE_NAME`), GSI `channel-user-turns`, `gsi1pk = CHANNEL_USER#whatsapp#<sha256(external_user_id)>`, `gsi1sk = TURN#<captured_at>#<trace_id>`. The external user id resolves to `whatsapp:+<national phone>` (sha256 prefixes: A `115974bf62c303d4…`, B `c6a0a6fda668e5d…`, C `2c7d9ab72efb6c69…`, D `ec02fcc31f15a93b…` — see Appendix A for the per-turn `external_user_hash` values). |
| `X` | Stored OpenAI extraction payload | `npm run audit:openai -- --response-id <extraction response_id>` (`src/audit/openai-audit-cli.ts`); structured output JSON in `calls[0].output[].content[].text`. |
| `R` | Stored OpenAI reply payload | `npm run audit:openai -- --response-id <reply response_id>`; reply text in `calls[0].output[].content[].text`, canonical turn evidence (order ids, payment status, thanks, reference) in `calls[0].input_items[0].content[0].text` → `customer_context`. |
| `G` | Live guest backend | `GET https://api.sinenvolturas.com/api/agent/guest/orders`, `.../guest/gift-purchases`, `.../guest/events` with `phone_extension=%2B51&phone_number=<national number>`, header `X-Agent-Key` (secret value never printed or stored). Queried 2026-10-20. |
| `M` | Live Agent API conversation log | `GET https://api.sinenvolturas.com/api/agent/conversations/messages?phone_number=+<national number>` (returns only the last 5 stored messages). Queried 2026-10-20. |

Base-URL note: the guest and conversation endpoints answered on `https://api.sinenvolturas.com/api/agent`; the
`https://api.sinenvolturas.com/api-web` base returns `{"status":false,"error":"Ruta no encontrada"}` for `/guest/*`. The production
Lambda configuration confirms `AGENT_API_BASE_URL=https://api.sinenvolturas.com/api/agent`.

## Redaction

Previews use the repo helper semantics (`redactSensitiveText`, `src/logs/trace/perf.ts`): e-mail → `[email]`, URL → `[url]`,
phone-shaped digit run → `[phone]`, standalone 4–8 digit run → `[code]`. The perf record stores the assistant preview already
redacted; the user preview is stored raw and was redacted here with the same rules.

No API key, token, OTP, customer phone number or e-mail appears in this file. Order/cart/reference identifiers
(`ORD_…`, cart ids, `COD…`/`cod:` references) are reproduced verbatim because the `orderIds` column is part of the
deliverable; they are backend identifiers, not secrets. Customer names, e-mails and the `voucher` image paths returned by
the guest API are deliberately omitted.

## Column semantics

- **Classifier health + reason** — `response_classifier.conversation_health` / `.health_reason` of the perf record. "no classifier call" means the turn carried no text body (image-only), so the reply classifier did not run.
- **Extraction informationRequests / routing** — from the stored extraction payload (`X`). `null` is what the extractor emitted; `none` means no request was emitted at all.
- **Backend read per source** — `information_execution_summary[].sourceCoverage[]` (`source:status/count`) plus the request-level `status` / `outcomeCode` / `resultCount`.
- **orderIds / paymentStatuses / referencePresent / thanksPresent** — from the canonical evidence the reply model actually received (`customer_context.purchases[]` in the stored reply payload): `orderId`, `paymentStatus`, `customerTransactionNumber` (null ⇒ no customer reference), `thanks` / `isThanked`.
- **Then vs now** — "then" = what the runtime read on that turn (perf record / stored payload); "now" = the live guest API on 2026-10-20.
- **Sources** — codes defined above; the identifiers are in Appendix A.
