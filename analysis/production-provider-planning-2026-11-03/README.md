# Production provider-planning incident — 3 November 2026

A WhatsApp customer asked for wedding catering options after providing location, guest count, budget and preferences. In the production record for the final request (trace `01M6FYHSEYRSN3VZR95Y4MK984`), the extraction intent was `buscar_proveedores`, but the projected schema lacked provider-planning fields. The persisted plan had no provider needs or location, `search_ready` was false, and the decision remained `ask_event_context`; no provider candidates were returned. The evidence is consistent with the screenshot. The customer identifier and private profile are deliberately excluded from this report.

The plan had returned to `entrevista`, with no pending information requests, but a historical completed FAQ kept `deriveEstablishedExtractionDomain` in the support lane. That hid the planning extraction schema and instructions on subsequent turns. The correction treats information work as active when the information node is current or an information request is pending; a completed request alone no longer owns future turns. Current support, purchase, and RSVP work retains its scoped extraction. No prompt text or keyword routing was added.
