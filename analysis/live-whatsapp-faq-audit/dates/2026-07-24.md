# 2026-07-24

## Question

What do live WhatsApp question traces reveal about unsupported gift/payment
answers, ambiguous fragmented messages, verification wording, duplicate
delivery, and Spanish-only language requirements?

## Commands Run

```bash
aws sts get-caller-identity --profile se-dev
aws dynamodb scan --profile se-dev --table-name recap-agent-runtime-perf ...
aws logs describe-log-groups --profile se-dev --log-group-name-prefix '/aws/lambda/recap-agent-runtime'
aws logs tail '/aws/lambda/recap-agent-runtime' --profile se-dev --since 30d --format short
jq ... /tmp/faq-scan.json
rg ... /tmp/recap-cloudwatch-30d.jsonl
```

The complete reproducible commands, including projection and aggregation
expressions, are in `../how-to-repeat.md`.

## Observations

- The table scan returned 35 WhatsApp question records from 1,914 scanned
  performance items.
- Manual review identified 24 transaction-related turns.
- Ten distinct native message identifiers appeared twice.
- The same “disable physical gifts” message received two different answers
  within 733 milliseconds. Other duplicate pairs disagreed about whether
  delivery referred to money or products.
- “El horario” was interpreted as business hours even though the prior
  fragments concerned a verification code and an event-related request.
- The payment mismatch turn asserted possible validation causes despite having
  no transaction lookup tool.
- CloudWatch retained the recent representative executions and recorded status
  `200`, successful delivery, and the same selected nodes. No infrastructure
  error explains the content failures.
- The log group retains seven days, so older duplicate executions can only be
  examined through the DynamoDB performance record.
- A deployed captionless image-descriptor probe returned the deterministic
  limitation in 526 milliseconds with no model or tool usage. DynamoDB and
  CloudWatch contained the same protected provider media identifier, media
  count, and image class.
- The complete categorized demonstration passed against the redeployed runtime.
  Its image case completed in 13 milliseconds inside the runtime with no model
  or tool calls. DynamoDB persisted feedback schema version 1, `media_only`
  input shape, deterministic routing, registered `image/jpeg` type, and the
  protected message correlation. CloudWatch exposed the matching message hash,
  one image, deterministic decision source, zero model calls, zero quality
  flags, and zero known Spanish-policy term warnings.
- A stakeholder rerun then exposed that “El horario” could land at confidence
  `0.55`, just above the former numeric ambiguity cutoff, and again answer
  customer-service hours. The corrected deployment uses typed ambiguity
  evidence with two explicit interpretations and preserves it as one neutral
  question. Trace `01KYAEMWGD2GMSY999P74X6EN4` was confirmed in both DynamoDB
  and CloudWatch through the protected message hash.

## Findings Promoted

- Capability boundary for all gift, sale, payment, withdrawal, balance, order,
  and claim cases.
- One-question clarification for ambiguous wording.
- Detailed code purpose/location/image instructions.
- Conservative email-space normalization.
- Temporary per-message burst persistence for replay and quality improvement.
- Spanish equivalents plus deterministic normalization for known leaked terms.
- An explicit provider-hosted media descriptor so actual WhatsApp images are
  proven by trusted request metadata rather than inferred from message wording.
- Versioned per-turn feedback signals so future reviews can group retries,
  isolate ambiguous or expensive turns, measure response complexity, and flag
  known Spanish-policy terms before joining the separate raw-message export.
