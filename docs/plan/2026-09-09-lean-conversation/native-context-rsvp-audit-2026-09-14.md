## Confirmed findings

1. **Live RSVP bypasses the durability component.** `src/runtime/agent-service.ts`, RSVP execution block around `guestRsvp`, directly writes, projects the write response into phone evidence, and composes the reply. `executeRsvpEffectDurably` has no runtime caller outside its own module. Its ordinary successful branch also performs zero state reads. Tests of that helper cannot establish live integration correctness.
2. **Returned identity and observed state are insufficiently bound.** `src/runtime/agent-conversation-gateway.ts` validates returned will_attend against requested action, but returns a supplied guest ID without rejecting a different returned guest ID. `applyRsvpMutationResultToPhoneEvidence` updates local invitations by event identity/name from result.action. A response echo is not independent confirmation of persisted backend state. This audit establishes a possible false-success path, not proof that the backend actually lost a particular production update.
3. **Correct time intent is erased.** Actual extraction requested payment_status AND payment_details and retained the 05:00-versus-17:00 question. `normalizePurchaseDetailRoute` in agent-service removes payment_details; its comment explicitly cites an orders-only hard gate. Reply evidence permits only payment_status and appends an instruction to answer only status. The model consequently omits time. This is a product regression caused by fitting routing to a test constraint.
4. **RSVP instructions contradict resolved evidence.** Tito turn 0 sends resolved_single authoritative invitation evidence alongside unresolved ambiguity and an instruction to ask which event. Turn 1 correctly extracts gratitude with no RSVP action, but enters the RSVP reply node, whose system prompt mandates attendance/event/date and a no-new-registration explanation. It also receives stale pending selection and next_action await_user_decision. The repetitive reply follows these instructions; it is not evidence that the model cannot respond naturally.
5. **Image failure manufactures unrelated intent.** Malformed/stale-image reply inputs include action_intent solicitar_humano with confidence 1, an escalation ranking note, planning categories and broad capabilities, despite the actual request asking about an unavailable image. There was no extraction call. Remove synthetic intent rather than adding an anti-handoff sentence.
6. **Native Files already exists.** `image-file-store.ts` uploads in-memory bytes with purpose vision and expiry; native input_image file IDs are supported in openai-agent-runtime. References are explicitly projected into replies. The Files expiry constant is 432,000 seconds (five days), so reported one-day doctrine has not uniformly reached code. Uploading a file alone does not attach it to future requests.
7. **Tests mix usability defects and evaluator defects.** Delia judge marks 3173.81 unsupported although the retrieved reply request contains that exact backend total and approved status. Stale-image judge demands mentioning an old internal reference and treats an OR recovery alternative as requiring both. Malformed-image v4 requires URL recovery and forbids resend, contrary to the current base64-first direction. s08 accurately says approved, but unnecessarily repeats it and adds an irrelevant balance caveat: understandable, with a real relevance problem, not a failed payment operation. Do not turn any of these historical failures green retroactively.

## Binding decisions for this amendment

- Preserve exactly three owners. State records evidence, pending user work, identity, authorization and effects. It must not supply a conversational script or remove a requested aspect to force a route.
- Preserve native Files upload for base64 and native image URLs when supplied. No object storage, separate vision summarizer, image-description message, or new backend package contract. Keep minimal conversation-scoped attachment references because this runtime does not use native provider conversation chaining. Do not introduce Conversations plus the existing manual history simultaneously; that would create two competing histories. Use existing explicit native image projection for this repair.
- Set new file retention to 86,400 seconds, matching the reported one-day direction. Honor actual expiry of existing references; do not pretend older five-day files were already deleted. Update stale five-day comments. Expiry is a media availability boundary, never a filter on historical purchases or conversational facts. Retention does not guarantee a storage quota at arbitrary traffic volume.
- Image/text in one invocation: one contextual answer. Text then image: retain earlier unresolved question and answer it from pixels when possible; do not repeat a delivered answer merely because an image arrives. Image then later text: persist the image reference and use it for the later question. Image alone without a pending question: persist without a user-facing description. No new debounce timers and no promise of one answer across independently delivered invocations; locks serialize known turns and cannot anticipate later messages.
- Unavailable pixels: answer from authorized existing evidence if sufficient; otherwise ask only for the specific missing factual information necessary to answer the user. Never request an image, re-upload, replacement attachment, or URL. URLs are backend-provided only. Never infer payment approval from a receipt.
- RSVP mutation is a single tool operation encompassing authorization, one write, authoritative read-back and an outcome receipt. The model chooses the requested action; the tool establishes what actually happened. A successful HTTP response alone cannot authorize success wording.
- Do not force an RSVP restatement on gratitude. Do not reoffer a change merely because current attendance is declining. Preserve valid current state internally while answering the current conversational act.

## Latest operator clarification — tools first, minimal questions, no scripted prose

This section supersedes all earlier recovery alternatives permitting image or URL requests, including earlier audit conclusions that treated resubmission as acceptable. Those conclusions were assessments under the prior requirement, not the current product contract. No customer-facing request for an image or URL is allowed. URLs can arrive from the backend only. The model may understand supplied images to help answer a request; no image-description workflow is required. A direct question about visible content can be answered naturally without a separate vision agent.

The design priority is capability-enabled model judgment with a small relevant context. Do not interpret prior requests for a detailed customer profile as an instruction to dump the full profile every turn. Retrieve authorized details necessary for the current question, expose complete relevant facts with provenance and unresolved alternatives, and retain handles for further inspection. Do not recursively fetch every unrelated record or inject every available capability. Answer what can already be established. Ask only when an essential fact remains unresolved after the applicable reads, or when authorization actually requires user involvement; do not add routine confirmations.

Exactly three owners remain. Transfer only current user intent, pertinent dialogue, resolved entity references, relevant facts/outcomes and pending work. The receiving owner must reuse these rather than restart onboarding or repeat questions. Backend attendance/payment state is authoritative; conversation state cannot manufacture a backend transition.

Every complete delivered conversational sentence is model-written. Code may supply typed facts, IDs, schema, receipts and factual UI values; it may not supply acknowledgements, questions, fallback replies, operational-note instructions masquerading as evidence, or templates filled with facts. Test cases are external observations of desired behavior, not branches or phrase dictionaries to install in runtime. Before adding a rule, identify and remove the competing instruction or missing-context cause.
