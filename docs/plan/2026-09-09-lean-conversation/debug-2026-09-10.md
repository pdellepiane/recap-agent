## Evidence and diagnosis

The original gate `eval-2026-09-10T03-03-13-259Z-30c88896` remains failed (81/83). It is not replaced by successful retries. Its close case contains all five original turns: close intent, name, email, phone, then explicit event date plus send authorization. On the fourth turn the extractor mislabeled the phone-only message as `proceed_confirmed`; the reply supplied the prompt example date `2026-10-18` to `finish_plan`. The fifth turn then caused a second write.

Stored response evidence was retrieved for extraction `resp_0b7fad46b7c9c594006aa224db4f9c87d2a0a49437fa400b9e` and reply `resp_0ae01800fc6e9e33006aa224dfbd2487d2be2adc64873b55c4`. Private local audit records remain in `.openai-audits/`; no raw customer context is published here.

Two code defects permitted the duplicate: model-provided dates were accepted without user provenance, and the caller ignored the executor's finished-plan update. A successful targeted run does not disprove either defect. Previous log language calling this merely stochastic/passable is superseded by this evidence.

The concurrency artifact has no completed turns and reports a missing active lock. The harness threw that message even when the first request had already rejected. Its original underlying request error was lost; successful retry alone does not prove a harmless infrastructure flake.

## Changes

- `src/runtime/close-submission-summary.ts`: corroborate normalized calendar dates against user-authored text. Do not accept prompt/model dates as provenance. Ambiguous date sets do not automatically enable submission.
- `src/runtime/openai-agent-runtime.ts`: hide `finish_plan` until user date evidence exists; validate again at execution; reuse same-turn confirmed effects; await persistence before continuing generation. The model retains response composition and structured intent extraction.
- `src/runtime/contracts.ts` and `src/runtime/agent-service.ts`: persist confirmed completion at the effect boundary and retain it on subsequent saves. Remove the finished-plan canned reply replacement.
- `src/evals/concurrent-turns.ts`: preserve the first request's actual rejection. Do not lower overlap requirements, increase thresholds, substitute sequential execution, or mark errored cases passed.
- Regression tests exercise original phone-only input, repeat tool execution, persistence despite subsequent generation failure, actual serialized tool omission, and error propagation. The legacy service test now checks preservation of model prose instead of expecting a deterministic rewrite.

## Limits

No universal exactly-once guarantee is claimed. A process failure between the external quote write and persisted completion still needs a durable idempotency design; partial-effect recovery across turns is also separate. Date matching validates provenance/formats, not all semantic associations between multiple dates and events. Unclear or unavailable dates keep submission unavailable. These limitations are not waived by an aggregate score.
