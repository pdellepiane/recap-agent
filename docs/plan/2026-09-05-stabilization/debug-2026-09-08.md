## Trace defects verified locally

1. **Projection is not idempotent.** `projectSafeTrace` runs at
   `handler.ts:497`, `targets/live-lambda.ts:154` and `reporting.ts:124`. With a
   search result containing two providers, one projection yields count 2 and two
   IDs; projecting that summary again yields count 0 and no IDs. The summary has
   `provider_ids`, while `countArrayField` searches raw collection fields. Other
   tool shapes need the same end-to-end test. A local expansion cannot recover
   data already replaced by `[omitted]` in an older Lambda response.
2. **The allowlist misses the failing boundary.** `request_human_takeover` is not
   handled by the projector. Purchase summaries retain kind/status but lose even
   emitted `result_count`. Called tools use `lookup_guest_orders_by_phone` while
   the output label is `agent_api_purchase_lookup` and input may be
   `agent_api_orders`; positional or name-only joining is unreliable.
3. **Free-text trace fields bypass text redaction.** `projectValue` returns string
   values unchanged unless their property name matches a sensitive key. A
   synthetic `operational_note` containing a phone survives projection. The saved
   multi-person trace contains a phone embedded in that field. Do not publish raw
   trace text as a workaround. Existing safety tests inject secrets mainly into
   fields the summary already ignores, not all allowed text fields.
4. **“Safe enum” is lexical, not an enum.** It accepts short arbitrary strings;
   numeric IDs and write receipt prefixes remain exposed. An ID-shaped canary
   survives by design, so current tests do not establish the stronger stated
   disclosure contract. Replace these with scoped opaque aliases in diagnostics,
   enumerated status values and receipt-presence facts. Bound provider completion
   arrays too; the special finish-plan path currently bypasses the common summary
   leak check and has no collection cap.

These findings contradict a blanket claim that trace work is complete. Existing
tests still pass: 33/33 across trace visibility, S09 projector and S16 capability
suites. The missing tests are transport composition, real producer shapes,
adversarial allowed fields and the integrated policy entry points.

## Exact trace contract to implement — S13, integrator owns wiring

Use a versioned typed diagnostic envelope. Emit structured summaries at the
decision/effect boundary, not by reparsing arbitrary tool JSON. Every subsequent
export validates and preserves the same envelope; unknown versions are omitted
with a typed reason. Never trust a caller-supplied `safe` flag. Keep all new
diagnostics outside model inputs: zero additional prompt bytes.

| Packet | Fields to retain | Emit when |
|---|---|---|
| Decision | support-act kind, auth-action enum, phone-confirmation enum, requested operation, request kinds/aspects, event-hint presence/provenance, rejection count/reasons, selected policy branch, pre/post auth status and method, pending-request count | At extraction normalization and arbitration for information/auth/capability turns |
| Human help | capability decision/reason, attempt ordinal, attempted, dedupe disposition, gateway status, bounded error enum, retryable, receipt present, persisted outcome, requested, soft-paused, OTP send/verify budget consumed | At every human-help decision, including skipped/failed paths |
| Purchase | resource, access method, coverage, reference resolution, reference supplied/authorized booleans, candidate count, per-candidate scoped alias, status enum, requested-field presence, amount source enum, anchor provenance, matched alias, selection reason, candidate counts before/after filtering | After canonical reconciliation and before reply projection; no raw amounts/names/references needed for this diagnosis |
| Reply | outcome kind, renderer ID or model stage, reason for deterministic/model choice, included field names, policy-fragment IDs, instruction/input bytes, final response digest | Before generation and after final rendering; existing response IDs retained for controlled retrieval |
| Effect/fixture | call ordinal shared by input/output/receipt, canonical operation, gateway kind (fixture/real/noop), scenario version/digest, fixture-state read (hit/miss/expired), idempotent replay boolean, bounded outcome/error enum, receipt present | Effect dispatch and completion; no physical keys, identities or receipt strings |
| Judge identity | digest of actual serialized redacted judge input, rubric/version digest, judge model/config, response digest, structural facts digest, individual hard scores | Evaluation only; compare judge-input identity separately from product-output identity |

Use per-turn ordinal aliases such as `candidate-1`; persist no reversible mapping
in exported diagnostics. Operation IDs are correlation ordinals, not backend IDs.
Allow only explicit enum values and numeric counts/booleans. Omit free-text
operational notes in exported traces in favor of branch IDs; keep user/assistant
transcripts behind the existing text-redaction path. Truncate candidate collections
at 8 and calls at 16, with total counts and truncation flags. Cap the serialized
new envelope at 8 KiB; on overflow drop candidate detail first, retaining outcome,
failure and truncation facts. Missing means `not_emitted`/`not_applicable`/
`redacted`/`truncated`, never a fabricated zero.

No additional provider tools or raw provider payloads are needed for the ten
failures. Preserve existing provider-close evidence on provider-close routes.
